# Baseline audit v2 Linux runtime (isolated proposal)

This is an inert, fixture-tested runtime proposal for canonical commit
`8e0bc9e73e0d85bff1d6261f384d8aebb37cac4c`. It is intended to be installed
root-owned mode 0755 and executed by a systemd service with `User=codexops`.

The runner validates separately root-owned, immutable mode-0444 external pin,
verifier release, runtime release, all code bytes, the historical producer manifest/executor and
all 474 checkpoint files before opening the read client. It executes exactly
three governed SELECT statements: combined dataset/session evidence, downstream
schema, and downstream counts. It then calls `finalize_live_audit` and creates
one mode-0600 append-only filesystem evidence file using `O_EXCL`.

There is no producer rerun, SQL write statement, local SQLite/CSV fallback,
model import, prediction generation, successor authorization, deployment, or
live execution in this proposal. The external pin is not generated by the
runner. The runtime release builder rejects the source base commit as its own
integration identity, so a runtime release and external pin can be established
only after a distinct canonical integration commit and Linux test evidence
exist. The included verifier-release candidate is valid for the already
integrated verifier at the stated base.

The service credential is deliberately separate: systemd must expose it as a
mode-0400 file owned by `codexops`. Requiring root ownership for that secret
would make `User=codexops` impossible and repeat the historical identity versus
fixture-ownership error.

Rollback is deletion of this isolated directory. No production state changed.
